方法: 两阶段轻量适配

Stage I 监督微调 (SFT) — 通道拼接 + LoRA

rectified flow 加噪 + 通道拼接 conditioning z_t = (1−t)·z_0 + t·ε,   ε ~ N(0, I)   →   ẑ_t = [z_t ; z_cond ; m]
flow matching 目标 (模型预测速度场 v = ε − z_0) L_FM = E[ ‖ v − v_θ(ẑ_t, t) ‖² ]

LoRA rank-64 更新 <1% 参数, VAE 和基座冻结。任务比"从零生成视频"窄 — 只需学会 condition 在劣化输入上, 因此 20 对视频就够。

Mask 该信谁, 该修谁

m=1 (训练视角): 保留不动, 防幻觉; m=0 (劣化帧): 修复。干净帧成为 anchor, 向相邻帧传播外观/光照/结构。无 mask 时模型分不清干净帧与轻度劣化帧, PSNR −1.3 dB。

Stage II Flow-DPO — 位姿精度作 reward

偏好优化 (Δ = 当前模型与 SFT reference 在流速预测上的 L2 差) L_DPO = −E[ log σ( −β/2 · (Δ_w − Δ_l) ) ]

reward = COLMAP (SuperPoint + LightGlue) 从输出恢复的相机位姿 AUC@5°; 每个场景 5 seeds 采样, 保留 AUC gap ≥ 0.2 的配对。解决"单帧合理但跨视图不一致"的幻觉。AUC@5° 61.1 → 68.3, PSNR 17.51 → 17.65, 零推理开销。

定位: 第一个"通用"渲染清理模型 — 不针对特定表示、无架构改动、数据需求低两个数量级。三个贡献: 表示无关的形式化、mask-aware conditioning、几何一致性偏好优化。

局限性与工程注意

论文自认: ①幻觉不可避免 — 模型必须在未观测区域"发明"内容, 只在"与已有观测矛盾"时才算失败; ②不确定性分析是 preliminary (5 seeds std), 无系统校准; ③长轨迹靠 61 帧分块, chunk 边界一致性靠共享 anchor, 有理论限制; ④评估以 DL3DV 大场景为主。
工程视角 (我的补充): ①代码未开源 (Coming Soon) — 与 PhysGS 同样问题, 复现要等官方 release; ②推理开销 — 31s/61帧 (H100, 5 steps), 视频扩散模型注定是离线预处理, 不是在线渲染; ③依赖 mask 标注 — 要知道训练视角集合与位姿, 位姿噪声会污染 mask; ④输出分辨率 480×832, 对需要高分辨率渲染的任务可能不够; ⑤20 对视频是"能用"不是"好用", 500 对才有完整效果。

对机器人项目的意义

补 GaussGym 渲染质量短板: GaussGym 用 3DGS 渲染器训练机器人, 稀疏扫描的 floaters 会污染视觉策略训练。FixAnything (3DGS 输入版, PSNR 17.65 @6 views) 可做离线清洗: 扫描 → 3DGS → 渲染轨迹 → 修复 → 干净训练视觉流。
稀疏点云路线可能跳过中间重建: FixAnything 证明 COLMAP 稀疏点云 + 视频先验就能出高质量渲染 (19.72 PSNR @9 views)。我们的扫描管线可以渲染点云轨迹 + 生成式修复, 省掉 NKSR mesh / 3DGS 训练 — 与 [[physical-property-estimation-from-scans]] 的结论呼应。
不确定性 = 补扫引导: 5-seed std 标出"模型在编"的区域 (弱观测区域), 指导哪里再多拍几张照片, 或把高不确定区域排除出策略训练采样。
与 PhysGS 互补: PhysGS 需要干净的 3DGS 重建才能准确估计物理属性; FixAnything 清洗后的渲染/重建可作 PhysGS 的输入增强。三篇综述 (GaussGym → PhysGS → FixAnything) 构成"场景获取 → 物理标注 → 渲染质量"的完整闭环。
落地路径: 等代码开源 → 用 GaussGym 扫描输出 (COLMAP 点云或 3DGS 渲染) 跑离线清洗 → 对比清洗前后策略训练表现。注意 31s/61帧 意味着批量离线, 不是实时。
